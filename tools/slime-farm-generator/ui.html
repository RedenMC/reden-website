计算口径与重要说明

搜索的“最大”具体是什么？

对范围内每个挂机方块的水平中心 P，统计满足 24² < ΔX²+ΔZ² ≤ 128² 的史莱姆区块内方块中心数量。24 格边界不计入，128 格边界计入。不按整区块估算，不只采样区块中心。通过严格上界排除不可能更优的区域，再逐格精查；同面积时优先距离世界原点近的位置，再按 X、Z 排序。这个结论不覆盖任意小数偏移的挂机点。

四种投影如何排列？

棋盘门保持原样。长条门与棋盘门的 Y1 相同，Y2 沿所选方向隔行排满门块；连续长度最多 21 格，超长时留一格空气。不切门 Y1 不放岩浆；Y2～Y4 是三格高门，Y5 为黑曜石顶框，Y6 默认平滑石下半砖。开启顶部游走时，顶层在地板外扩五格；关闭时只覆盖所有顶框黑曜石及刷怪地板外侧的黑曜石柱。超长不切门插入黑曜石柱。长条门与不切门会按相邻史莱姆区块组成的连通区域选择 X 或 Z：仅 X 向相邻时改为 Z，仅 Z 向相邻时保持 X；两个方向都有时，门沿相邻连接数更多方向的垂直方向排列，相同则取 X。每个区域各自选方向。P 的 Y2 放空堆肥桶。

版本与真实刷怪的边界

提供 Java 1.16～26.3 的目标版本选项，使用 Java 传统史莱姆区块公式。1.18 前地板 Y 默认 0，之后默认 −64；版本还约束可选材料，Litematic v5 的 MinecraftDataVersion 取自所选正式版服务端。导入主世界存档后，按刷怪高度排除已保存区块中的深暗之域与古城范围；未保存区域仍按可刷计，结果会标出覆盖缺口。降雪文字是施工风险提示，需检查露天方块与实际天气。地狱门换算使用主世界 X/Z ÷8、Y 不缩放；本机 1.21.10 服务端确认地狱侧横向搜索半径 16，选门计入 Y。

按你的要求使用单层水平圆环，暂不计玩家脚部和刷怪脚部的高差；堆肥桶站位会带来微小高差，严格球形边界可能相差少量格子。Y2（刷怪脚部层）须低于 40。真实自然生成还取决于主世界、地形和生物群系、出生空间、世界出生点、其他玩家、模拟距离、难度及怪物上限；本程序只读取用户选择的存档群系与古城结构，不读取地形方块，也不会把面积当成保证产量。建造前请在备份或测试存档中核验区块与切门状态。
